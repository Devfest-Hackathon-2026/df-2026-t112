# EVC 仕様書(MVP)

## 目的

AI を使って作ったアプリのコードを、作った本人がどれだけ理解しているかを測り、学習につなげる。

## MVP のスコープ

含める:

- 公開 GitHub リポジトリの URL 入力
- Gemini による問題生成(テストやサンプルを除いた本体のコードの総量に応じて 4〜18 問。5KB 未満は 4 問、60KB 未満は 6 問、400KB 未満は 12 問、それ以上は 18 問)
- 回答、採点、結果表示(総合スコア、説明力、総評)

含めない(MVP 後):

- ログイン: GitHub でログインした人だけが使える。一般公開までは、許可リスト(GitHub の数字の ID)に入っている人だけ。ログインした本人の GitHub トークンで、非公開リポジトリも読める
- アカウント機能: 履歴、間違えた問題集など(#34、#37 で設計中)
- 出題の範囲: ログイン中の本人が書いて今も残っている行(blame で判定)から自動で出題する。本人のコミットが無いリポジトリは全体から出題する。PR の作成者ではなくコミットの著者を基準にする
- 間違えた問題の復習: 間違えた問題をアカウントごとに保存し(`users/{uid}/mistakes`)、選択式も記述式に作り変えて一問一答で復習する。0.7 点以上で解決済みにする。解決済みの問題もフォルダに残し、未解決と分けて見られる。解き直しもでき、0.7 点に届かなければ未解決に戻す
- 続けて解く: 間違えた問題があれば類似問題(3〜6 問)、全問正解なら同じリポジトリのまだ解いていない問題(6 問)
- AI が課題を出して人間が実装する元のモード
- AI が実行した UI を見せる出題(悪意あるコードの実行リスクがあるため)

## ユーザーフロー

1. GitHub でログインする。
2. URL 入力画面でリポジトリの URL を送る。
3. API が GitHub からコードを取得し、Gemini が問題を生成する。
4. 出題画面で全問に回答する(ヒントは任意で表示)。回答は 1 問ずつサーバーに保存するので、再読み込みしても、別のタブや端末で開いても、続きから解ける(URL にクイズの ID が入る)。
5. 採点後、結果画面にスコアとフィードバックを表示する。

## 問題

| 種類 | 数 | 内容 |
|---|---|---|
| 選択式 | 15 | 4択。関数の役割、処理の流れ、言語・FW の知識(例: `SerializeField`、コルーチン) |
| 記述式 | 3 | コードの説明を文章で答える。AI がルーブリックで採点する |

各問題は次の項目を持つ。

- `id`
- `type`(`choice` / `free`)
- `category`(採点軸のいずれか)
- `difficulty`(1〜3)
- `question`
- `codeRef`(対象ファイルと行範囲)
- `choices` と `answerIndex`(選択式のみ)
- `rubric`(記述式のみ)
- `hint`
- `explanation`

## 採点軸(内部の 5 項目。画面には表示しない)

| 軸 | 意味 |
|---|---|
| コード読解 | 個々の関数・処理が何をするか |
| 設計・全体理解 | ファイルやモジュールの役割と依存関係、アプリ全体の目的と流れ |
| 言語/FW知識 | 使われている API・概念の知識 |
| エラー処理・テスト | 例外、境界条件、テストが確かめていること |
| セキュリティ | 認証や認可、入力の検証、秘密情報の扱い(コードに根拠が無ければ他のカテゴリに差し替える) |

- 各軸は 0〜100 点。その軸の問題の得点率で算出する。
- 総合理解度は 5 軸の平均。カテゴリの得点では記述式の重みを選択式の半分にする。記述式の平均は「説明力」として別に表示する。
- 記述式の採点と AI の総評は、Gemini への 1 回の呼び出しでまとめて行う(無料枠のリクエスト数を節約するため)。
- 総評は AI が生成し、「理解できていること」「理解が足りないこと」「次にやること」を具体的に述べる。

## 非機能

- 入力は GitHub の公開リポジトリ URL のみ。他の host は受け付けない。
- 取得するファイル数、サイズ、トークン量に上限を設ける。
- バイナリ、ロックファイル、`node_modules` などは除外する。
- Gemini の API キーは Secret Manager で管理し、フロントに出さない。
- 取得したコードは実行しない。
- コードのコメントは、画面と AI への入力から取り除く(コメントに答えが書かれていて、出題の意味がなくなるのを防ぐため)。Markdown や JSON などはそのまま。

## 未決事項(検証しながら決める)

- 問題の難易度配分
- Gemini が記述式を安定して採点できるか
- Web アプリ以外のリポジトリ(Unity など)への対応範囲
